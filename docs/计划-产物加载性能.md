# 产物加载性能（长图录首屏与跳转）实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 158 页图录产物「打开到能看见书」从**下载 58.6 MB / 等 24.3 秒**降到
**约 1.1 MB / 约 1 秒**，同时不让跳转和翻页变得卡顿。

**Architecture:** 翻页库 `vysmo-flipbook` 在 `lazy: true` 时本来就只加载「当前页 ±
`preloadWindow`」就 ready，翻页也只等这一小窗口。瓶颈是 `12-bookpage.js` 的 `bootFlip()`
自己又做了一遍全量预检（`new Image()` × 页数），并让 `initFlip()` 等到**所有页** decode
完才调用。本计划把预检收窄到首屏那几页，其余交给库；再用「跳转前预取」和「不再剔页、
改补占位图」补上收窄带来的两个副作用（跳转变慢、坏图页导致页码错位）。

**Tech Stack:** 纯 ES5 浏览器 JS（无打包器）。源码 `build/js/*.js` 由
`build/build.py` 按 `JS_ORDER` 顺序拼接进 `build/shell.html` 生成 `studio.html`。
测试是 Python + Playwright 探针，放 `build/.verify/`。

**设计文档:** `docs/批量导入图-设计.md` §12（含 12.1 实测表）。

### Task A1: 预检收窄到首屏 + 缺图页补占位图（不再剔页）

**Files:**
- Modify: `build/js/12-bookpage.js`（`sheetList` 的 `srcOf`，约 30-33 行；**`PAGES` 的定义，第 501 行**；`bootFlip()`，约 2100-2147 行）
- Test: `build/.verify/probe_flip_pages.py`（新建）

**Interfaces:**
- Consumes: `PAGES`（数组，元素 `{ kind, src, items, title }`）、`PRELOAD`（数字，
  来自 `p.bookPreload`，默认 2）、`PREVIEW_FIRST`（布尔）、`initFlip()`、`hideBoot()`、
  `bootProg(done, all)`、`total`
- Produces: `blankSrc()` —— 返回一个占位图的 data URL（首次调用时用 canvas 生成并缓存）。
  Task A2 会复用 `PAGES` 与 `total`。

#### 背景（为什么这么改）

`bootFlip()` 现在对**每一页**做 `im.src = pg.src`，并让 `initFlip()` 等到
`left === 0`（全部结束）。158 页时这等于先下完 58.6 MB 才显示书。

**缺图页在建翻页器之前就被剔过一次了** —— 第 501 行：

```js
'var PAGES = SHEETS.filter(function (s) { return !!(s && s.src); });',
'var total = PAGES.length;',
```

「没上传图片的页」正是最常见的空 src 来源：`sheetList` 的 `srcOf` 在没图时返回**空字符串**，
而 files 模式下更糟 —— 会指向一个不存在的 `book/page-N.jpg`。

这一步发生在 `bootFlip()` **之前**，所以**光在 `bootFlip` 里补占位图是没用的**：
那些页压根进不了 `PAGES`，补占位图的代码永远不会执行。**必须先把 501 行的过滤去掉。**

然后 `bootFlip()` 里还有第二次剔除：

```js
PAGES = keep.filter(function (x) { return !!x; });
```

它会把预检失败的页**删掉**，后面所有页整体前移 —— 158 页里坏 1 页，第 5 页的图就显示在
第 4 页上，页码和图全面错位。

所以三件事一起做：
1. 501 行不再按 `src` 过滤（保留全部槽位）；
2. 预检收窄到首屏；
3. 坏页 / 缺图页统一改为「换占位图」，不再删页。

  var D = '/build/.verify/e2e/perf/book/';
  var st = window.SD.STATE;

  st.title = '占位图测试';

    cover: { url: D + 'cover.jpg', name: 'cover.jpg', w: 900, h: 1200 },

      { url: '', name: '', items: [] },
      { url: D + 'page-3.jpg', name: 'page-3.jpg' },
      { url: '', name: '', items: [] }

    back: { url: D + 'back.jpg', name: 'back.jpg' }

  return window.SD.Codegen.buildHtml(st, { mode: 'files' });

            p0.goto(BASE + '/studio.html', wait_until='load')
            p0.wait_for_function('!!window.SD && !!window.SD.Codegen', timeout=20000)
            p0.wait_for_timeout(700)

            os.makedirs(os.path.join(ROOT, FIX), exist_ok=True)

            page.goto('%s/%s/%s' % (BASE, FIX, OUT), wait_until='commit')

            page.wait_for_timeout(2500)

              var ps = window.__pages || [];

            print('翻页器页数 :', st['fbPages'])

                bad += 1

                bad += 1

        srv.terminate()
    print('结果：', 'FAIL' if bad else 'OK')
    return 1 if bad else 0

    sys.exit(main())

### Task A2: 跳转前预取 + 加载反馈 + `fb.goTo` 异步兜底

**Files:**
- Modify: `build/js/12-bookpage.js`（`goToPage()`，约 1114-1118 行；`buildCss` 里加一条样式；`buildBody` 或 `buildInit` 里加提示元素）

**Interfaces:**
- Consumes: `PAGES`、`total`、`cur`、`fb`、`PRELOAD`、`blankSrc()`（Task A1 产出）
- Produces: `preloadPage(n, cb)` —— 预取第 `n` 页（1 基）及其前后 `PRELOAD` 页，
  全部结束后调用 `cb()`；`showJumpTip(text)` / `hideJumpTip()`。

#### 背景

收窄预检后，跳到一个没预取过的页要现场加载。库的 `goTo` 内部会
`await X(h)`（等目标页 ± k 加载完）才切页，这段等待**没有任何反馈**。

而且现有写法拦不住异步失败：

```js

```

### Task A3: 拖进度条的过程中就预取

**Files:**
- Modify: `build/js/12-bookpage.js`（`seekRange` 的 `input` 监听，约 1134-1137 行）

**Interfaces:**
- Consumes: `preloadPage(n, cb)`（Task A2 产出）
- Produces: 无新接口

#### 背景

`input` 在拖动过程中连续触发，现在只更新提示文字（`seekTip`），**不预取**。
所以松手那一刻才开始加载目标页 —— 拖动过程本来正好是免费的准备时间，浪费了。

**节流的正确做法**：`seekRange` 是 `<input type="range">` 且**没有 `step` 属性**（默认 1），
所以拖动时它的值几乎**每次 `input` 都不同**。因此「同一个目标页只预取一次」
（`v !== _seekPre`）在实际拖动里几乎拦不住 —— 跨 K 页就是 K 次 `preloadPage`，
而每次 `preloadPage` 又会拉上前后 `PRELOAD` 页，等于一次拖动打出约 `5K` 个请求。
必须用 **debounce**：拖动停下 120ms 后才预取「停留的那一页」及其前后页。

- [ ] **Step 1: 在 `input` 里加 debounce 预取**

把现有的：

```js
      '  seekRange.addEventListener("input", function () {',
      '    var v = parseInt(seekRange.value, 10);',
      '    if (seekTip && isFinite(v)) seekTip.textContent = "第 " + v + " 页";',
      '  });',
```

替换为：

```js
      '  /* 拖动时连续触发（range 没有 step，跨 K 页就是 K 次不同的值），',
      '     所以 debounce：停下 120ms 才预取「停留的那一页」。',
      '     为什么不是「按目标页去重」：拖动时值几乎总在变，去重拦不住 ——',
      '     跨 50 页就是 50 次 preloadPage，每次又拉前后页，等于一次拖动几百个请求。 */',
      '  var _seekPreT = 0;',
      '  seekRange.addEventListener("input", function () {',
      '    var v = parseInt(seekRange.value, 10);',
      '    if (seekTip && isFinite(v)) seekTip.textContent = "第 " + v + " 页";',
      '    if (!isFinite(v)) return;',
      '    if (_seekPreT) clearTimeout(_seekPreT);',
      '    _seekPreT = setTimeout(function () {',
      '      _seekPreT = 0;',
      '      preloadPage(v, function () {});',
      '    }, 120);',
      '  });',
```

做法：劫持 `window.Image` 计数（或数网络请求），模拟「连续派发 8 个不同值」的 input
